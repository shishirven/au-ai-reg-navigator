# Chunking ablation: one chunk per paragraph vs fixed-size windows

35 answerable DRAFT questions (`data/eval/questions_draft.jsonl`) and 8 broad DRAFT questions (`data/eval/broad_questions_draft.jsonl`); retrieval only, no LLM. Every config uses the default retrieval (`hybrid_stratified_capped`: hybrid dense + BM25 per legal-force tier, query expansion, cross-encoder re-ranking, 4 chunks per tier); only the chunking differs. Generated by `scripts/chunking_ablation.py`.

A gold paragraph counts as reaching the model when >= 80% of its 3-word shingles are in the retrieved chunks from its document, the same rule for every index. *Same tokens* cuts each fixed-window list at the paragraph run's context size for that question.

## Reading it (25 Nov 2026)

* **Per token of context, paragraph chunks win clearly.** Given the same context size, fixed
  512-token windows get the gold paragraph text to the model far less often (recall 0.50 vs 0.75,
  paired Δ −0.25 [−0.36, −0.15]) and miss the right binding paragraph much more often
  (0.65 vs 0.91, Δ −0.26 [−0.43, −0.09]). 256-token windows are worse at either budget.
* **Fixed 512 only draws level by sending 2.5× the text.** At the same chunk count (12) it is
  within noise on recall (−0.04 [−0.14, +0.05]) and equal on the right binding paragraph, and it
  covers more of the broad questions (0.70 vs 0.61), but with 6,179 context tokens per question
  instead of 2,490. On the Groq free tier (8,000 tokens per minute, prompt and output included)
  that leaves almost no room, and every answer would cost about 2.5× as much on a paid model.
* **Windows can't be cited.** A retrieved 512-token window spans about 5.8 source paragraphs
  (256: 3.1; paragraph chunks: 1.3, from small merged paragraphs and heading sections). An answer
  built on a window can say "CPS 230, page 14" but not "CPS 230 para 52", and the validator can no
  longer tell a `must` paragraph from a `should` one inside the same window, because modality is
  tagged per chunk (F-07 gets worse).
* **Window size cuts against the models.** 512 estimated tokens plus the header line reaches
  BGE-small's 512-subword input limit and the cross-encoder's 512 limit for query plus passage, so
  the tail of a window is often not embedded or scored. Smaller windows fit but split obligations
  from their lead-in ("must:") and lose more.

**Decision:** keep paragraph chunking (D-058). The citation argument now has a measurement behind
it: paragraph chunks reach the right text with less than half the context, and they are the only
option that keeps paragraph citations and the must/should check.

**Caveats.** Developer-written DRAFT questions whose gold labels are paragraphs, so the scoring
unit is the paragraph by construction; the 80% text rule is applied identically to every index,
but a question whose answer spans a boundary favours neither. Retrieval only: answer quality with
fixed windows was not generated (the 12-window context does not fit the free tier reliably).
Reproduce with `uv run python scripts/chunking_ablation.py configs/hybrid_stratified_capped.yaml
configs/ablation_fixed512.yaml configs/ablation_fixed256.yaml` after
`uv run python -m regnav.cli ingest --config configs/ablation_fixed512.yaml` (and 256).
