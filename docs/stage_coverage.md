## The other side: narrow questions (40 DRAFT questions, retrieval only)

Each fix was also run on the 40 draft questions, which mostly target one or two specific
paragraphs. A fix that helps broad questions must not cost these.

| config | context recall | binding gold paragraph | recall@5 | broad stage coverage |
|---|---|---|---|---|
| `hybrid_stratified_rerank` (default) | 0.740 | 0.913 | 0.618 | 0.43 |
| same, re-ranking 40 candidates per tier instead of 20 | 0.723 | 0.870 | 0.618 | n/a |
| + soft cap 2 per document | 0.715 | 0.826 | 0.618 | n/a |
| + soft cap 3 per document | 0.748 | 0.913 | 0.618 | 0.62 |
| **+ cap 3 + instruction stripping (`hybrid_stratified_capped`)** | **0.748** | **0.913** | **0.618** | **0.67** |
| + stage sub-queries (no cap) | 0.682 | 0.870 | 0.583 | 0.69 |
| + cap 3 + stripping + stage sub-queries | 0.691 | 0.870 | 0.583 | 0.67 |
| + cap 2 + stripping + stage sub-queries | 0.672 | 0.783 | 0.583 | 0.61 |

Reading it:

* **The per-document cap fixes F-12** (B03: the APP 1.7-1.9 fact sheet now reaches the context)
  and costs nothing on narrow questions. A cap of 3 is enough; 2 starts removing genuinely needed
  paragraphs from CPS 230, the main binding document for vendor questions.
* **Instruction stripping** only matters when a question carries formatting instructions (B02,
  0.20 → 0.60); otherwise it is a no-op.
* **Stage sub-queries** add coverage only on top of the uncapped config; with the cap they add
  nothing here and cost narrow-question recall (the question's own second-best hit loses its slot
  to a stage hit). They stay **off in Q&A** and are used where breadth is the point: the
  model-use check, which searches every stage separately (D-053).
* n = 8 broad and 40 narrow developer-written questions: the broad-question intervals overlap, so
  this is directional evidence. The generation eval of `hybrid_stratified_capped` decides whether
  it replaces the default.
