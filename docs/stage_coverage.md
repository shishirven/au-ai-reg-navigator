## The other side: narrow questions, and answer quality

Each fix was also run on the 40 draft questions, which mostly target one or two specific
paragraphs (retrieval only, then a full generation eval where noted). A fix that helps broad
questions must not cost these.

| config | context recall | binding gold paragraph | broad stage coverage | answer correctness (paired Δ vs re-rank) |

| `hybrid_stratified_rerank` (default) | 0.740 | 0.913 | 0.43 | 0.887 |
| re-ranking 40 candidates per tier instead of 20 | 0.723 | 0.870 | n/a | |
| + soft cap 2 per document, all tiers | 0.715 | 0.826 | n/a | |
| + stage sub-queries (no cap) | 0.682 | 0.870 | 0.69 | |
| + cap 2 + stripping + stage sub-queries (first proposal) | 0.672 | 0.783 | 0.61 | |
| + cap 3 + stripping + stage sub-queries | 0.691 | 0.870 | 0.67 | |
| + cap 3, **all tiers** + stripping (`…capped_alltiers`) | 0.748 | 0.913 | 0.67 | 0.844 (−0.04 [−0.12, +0.02]) |
| **+ cap 3, guidance tiers only + stripping (`hybrid_stratified_capped`)** | **0.750** | **0.913** | **0.61** | generation eval scheduled |

Reading it:

* **One document taking every slot (F-12) is a guidance-tier problem.** The cap fixes it (B03:
  the APP 1.7-1.9 fact sheet now reaches the context) and lifts broad coverage.
* **In the binding tier the relevant standard should dominate.** Capping it replaced needed CPS 230
  paragraphs (para 53 contract terms, para 28, para 48) with less relevant CPS 234 / CPS 220 ones;
  answer correctness fell on exactly those questions (D02, D06, D34). The final config leaves the
  binding tier exactly as in `hybrid_stratified_rerank` (identical binding context on 40/40
  questions).
* **Instruction stripping** only matters when a question carries formatting instructions (B02,
  0.20 → 0.40 with the guidance-tier cap, 0.60 with the all-tier cap); otherwise it is a no-op.
* **Stage sub-queries** cost narrow-question recall (the question's own second-best hit loses its
  slot) and add little on top of the cap. They stay **off in Q&A** and are used where breadth is the
  point: the model-use check searches every stage separately (D-053).
* n = 8 broad and 40 narrow developer-written questions; the broad-question intervals overlap, so
  this is directional evidence. `hybrid_stratified_capped` replaces the default only if its
  generation eval is at least as good as `hybrid_stratified_rerank`.
