| D-016 | **PDF parsing heuristics:** body size = most common font size; spans more than 1.5pt smaller are dropped (footnotes, superscript references); short lines that recur on at least 40% of pages *and* sit in the top or bottom 12% of the page are dropped (running headers and footers); headings are lines ≥1.5pt larger than body, or ~1pt larger and short, or bold at body size and not a table cell. | Tuned by inspecting all 6 PDFs (single- and two-column layouts). Covered by unit tests on generated PDFs. |
| D-017 | **Token counts are estimated with a regex (`\w+` or punctuation) rather than the embedding tokenizer.** Structural chunks are kept to ≤350 estimated tokens, with tiny units merged below 25. | Fast and dependency-free. 350 estimated tokens stays under BGE's 512-token input limit, so chunks are not silently truncated. |
| D-018 | **Chunk ids are deterministic and human-readable**: `apra_cps230_2026:p52` = CPS 230 para 52. Suffixes: `.k` (split piece), `p5-6` (merged), `~2` (duplicate number, e.g. in an attachment), `s007` (heading section). | Gold labels in `questions.jsonl` refer to these ids, so they must stay stable across re-ingests. `make chunks DOC=...` lists them. |
| D-019 | **The ingest-code hash is part of every document's fingerprint.** | Changing the parser or chunker invalidates the index in the same way as changing a source file: a new `index_version`, which the release gate requires a re-evaluation for. |
| D-020 | **Index version = content hash** of (embedding + chunking config, every doc's sha256, its metadata and the code hash). | Rebuilding identical inputs gives an identical version (idempotent), and any change gives a new one. |
| D-021 | **The LLM provider is configurable: `ollama` (default, free, local), `anthropic` or `stub`.** Default generator `qwen3:4b`; judge `gemma3:4b` (a different model family, to limit self-preference bias). | User decision (no paid API). Provider abstraction is also a supplier-risk control: the model can be swapped and re-validated without code changes. |
| D-022 | **Default generator is `qwen3:4b` rather than `qwen3:8b`.** | Measured in this container (4 vCPU, CPU only): ~3.5k-token prompt → ~90–210 s per answer with 4B. 8B is roughly 2× slower, which makes a 90-answer eval impractical on a 16 GB CPU laptop. 8B remains a one-line config change (`--model qwen3:8b`). |
| D-023 | **Ollama JSON: schema in the prompt, no grammar-constrained decoding** (`ollama_format: none`). Our validator parses and checks the output and retries once. | Empirical: with Ollama's `format=<schema>`, Qwen3-4B abstained on a question its sources clearly answered (twice). Without the constraint it produced a well-formed, correctly cited answer. Constrained decoding with thinking disabled appears to push small models to the empty, schema-valid answer. Modes `json` and `schema` remain selectable. |
| D-024 | **Prompt v2: abstain only if *no* source is relevant; partial, cited answers preferred.** The tech-neutral link is spelled out (an AI vendor is a service provider; an AI system is an information asset). | v1's stricter abstain rule caused over-abstention on small models. | D-025 | **Stratified merge = per-tier RRF scores, interleaved by within-tier rank (binding first on ties).** Stratified top-k = 3 tiers × `per_tier_k` (3) = 9 = pooled `top_k`. | Equal context budgets make the configs comparable; the interleaving keeps rank-based metrics (MRR) meaningful. |
| D-026 | **The safe fallback is an explicit abstention** after one failed repair attempt or an LLM outage, flagged `fallback=true`. | An unvalidated answer is never shown. Fallback rate is a monitored metric. |
| D-027 | **Langfuse traces are written after the answer completes** (spans for retrieval and for each generation attempt, with tokens, cost, latency, validation errors, config name and index version).
