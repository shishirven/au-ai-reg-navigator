# Decisions log

Choices made without asking, so they can be reviewed. Newest last.

| ID | Decision | Why / alternatives |
|----|----------|--------------------|
| D-001 | **Python 3.12**, `requires-python >=3.11,<3.13`. | Within the brief's 3.11+; 3.12 has wheels for every dependency (torch, chromadb, pymupdf). |
| D-002 | **CPU-only torch from the PyTorch CPU index for every platform** (`[tool.uv.sources]`), lock restricted to linux x86_64/aarch64 + macOS. | The brief asks for CPU torch in Docker; using it everywhere keeps one `uv.lock`, keeps CI fast and avoids multi-GB CUDA wheels. |
| D-003 | ~~Generator Claude Opus, judge Claude Sonnet~~ → **superseded by D-021.** The Anthropic path is kept as `configs/claude_stratified.yaml`. | User chose free local models. |
| D-004 | **Temperature 0 + fixed seed for Ollama** (honoured). **For Claude, sampling parameters are never sent**, because current Claude models reject them. | With Claude, determinism instead rests on the fixed prompt, structured output, a pinned lock and versioned indexes; run-to-run variance is measured rather than assumed away. |
| D-005 | **Structured output through `output_config.format` (JSON schema)**, then our own post-hoc validator (`generate/validate.py`). | The schema guarantees parseable JSON. Semantic rules (citations in the retrieved set, tier/section consistency, modality) need our own code either way, and that code can be unit-tested with a stub LLM. |
| D-006 | **Two embedding backends:** `sentence_transformers` (BGE-small, the default for all real configs) and a deterministic `hashing` bag-of-words backend. | The hashing backend lets unit and integration tests run hermetically (no model download, no network). The CI retrieval regression gate uses the **real** BGE model, with the model cached between runs. |
| D-007 | **Fixture corpus stored as `.txt` and rendered to PDF at test time** (`regnav/fixtures.py`). | The fixtures stay readable and diff-able in git, while the real PyMuPDF parsing path (including font-size heading detection) is still exercised end-to-end. |
| D-008 | `data/sources.yaml` metadata (title, url, effective_from, status) is copied from the user's `data/raw/manifest.csv`, not inferred. A `file` field maps each entry to its file in `data/raw/`. | Per the brief: don't guess. Where the manifest gives only a month (CPG 235: "September 2013") the 1st of the month is used, with a comment. |
| D-009 | **Tiering of the 12 sources:** CPS 230/220/234 are `binding`; CPG 230, CPG 235, the APRA AI letter and both OAIC documents are `expectation`; AI6 Foundations, the Voluntary AI Safety Standard and the AI Ethics Principles are `voluntary`. | PPGs "do not themselves create enforceable requirements" (CPG 230 p2). The OAIC fact sheet explains a *binding* Privacy Act obligation (APP 1.7–1.9), but the document itself is regulator guidance, so its tier is `expectation`. This limitation is documented in the model card: the fix is to add the Privacy Act / APP text itself as a binding source. |
| D-010 | **Sector filter semantics:** a document is in scope for sector *S* if `applies_to` contains *S* **or** `any_business`. | Voluntary, economy-wide guidance applies to banks too; excluding it would remove the "Recommended" tier for every sector. |
| D-011 | GitHub repo was created by the user; Phase 1 was rebased onto their initial commit (sources + manifest). | This session cannot create repositories. |
| D-012 | **Markdown sources supported alongside PDFs.** 6 of the 12 sources are web pages the user saved as `.md`. The provenance header (issuer, retrieved date, `---`) is stripped before chunking. | That header is metadata, already in `sources.yaml`; embedding it would add noise to every first chunk. |
| D-013 | **Superseded documents are indexed but excluded from retrieval by default** (`status: superseded`: CPS 230 2023, VAISS 2024, AI Ethics Principles 2019). | Keeps answers on current law while still allowing version-evolution questions when `include_superseded` is turned on. |
| D-014 | **Per-document parse hints live in `sources.yaml`** (`structure: numbered/headings`, `start_page`/`end_page`, `drop_boxed_text`) rather than in heuristics only. | They are explicit, reviewable and testable: the determination cover pages, TOCs and back covers are skipped by page range. |
| D-015 | **CPG 230's blue boxes (verbatim quotes of CPS 230 paragraphs) are dropped** (`drop_boxed_text`). | Otherwise binding text would be indexed a second time under an `expectation` label, which is exactly the authority confusion this project is trying to remove. The binding text is still indexed once, from CPS 230 itself. |
| D-016 | **PDF parsing heuristics:** body size = most common font size; spans more than 1.5pt smaller are dropped (footnotes, superscript references); short lines that recur on at least 40% of pages *and* sit in the top or bottom 12% of the page are dropped (running headers and footers); headings are lines ≥1.5pt larger than body, or ~1pt larger and short, or bold at body size and not a table cell. | Tuned by inspecting all 6 PDFs (single- and two-column layouts). Covered by unit tests on generated PDFs. |
| D-017 | **Token counts are estimated with a regex (`\w+` or punctuation) rather than the embedding tokenizer.** Structural chunks are kept to ≤350 estimated tokens, with tiny units merged below 25. | Fast and dependency-free. 350 estimated tokens stays under BGE's 512-token input limit, so chunks are not silently truncated. |
| D-018 | **Chunk ids are deterministic and human-readable**: `apra_cps230_2026:p52` = CPS 230 para 52. Suffixes: `.k` (split piece), `p5-6` (merged), `~2` (duplicate number, e.g. in an attachment), `s007` (heading section). | Gold labels in `questions.jsonl` refer to these ids, so they must stay stable across re-ingests. `make chunks DOC=...` lists them. |
| D-019 | **The ingest-code hash is part of every document's fingerprint.** | Changing the parser or chunker invalidates the index in the same way as changing a source file: a new `index_version`, which the release gate requires a re-evaluation for. |
| D-020 | **Index version = content hash** of (embedding + chunking config, every doc's sha256, its metadata and the code hash). | Rebuilding identical inputs gives an identical version (idempotent), and any change gives a new one. |
| D-021 | **The LLM provider is configurable: `ollama` (default, free, local), `anthropic` or `stub`.** Default generator `qwen3:4b`; judge `gemma3:4b` (a different model family, to limit self-preference bias). | User decision (no paid API). Provider abstraction is also a supplier-risk control: the model can be swapped and re-validated without code changes. |
| D-022 | **Default generator is `qwen3:4b` rather than `qwen3:8b`.** | Measured in this container (4 vCPU, CPU only): ~3.5k-token prompt → ~90–210 s per answer with 4B. 8B is roughly 2× slower, which makes a 90-answer eval impractical on a 16 GB CPU laptop. 8B remains a one-line config change (`--model qwen3:8b`). |
| D-023 | **Ollama JSON: schema in the prompt, no grammar-constrained decoding** (`ollama_format: none`). Our validator parses and checks the output and retries once. | Empirical: with Ollama's `format=<schema>`, Qwen3-4B abstained on a question its sources clearly answered (twice). Without the constraint it produced a well-formed, correctly cited answer. Constrained decoding with thinking disabled appears to push small models to the empty, schema-valid answer. Modes `json` and `schema` remain selectable. |
| D-024 | **Prompt v2: abstain only if *no* source is relevant; partial, cited answers preferred.** The tech-neutral link is spelled out (an AI vendor is a service provider; an AI system is an information asset). | v1's stricter abstain rule caused over-abstention on small models. The explicit link is the generation-side half of the core idea: retrieval puts CPS 230 in context, and the prompt lets the model connect it to AI. |
| D-025 | **Stratified merge = per-tier RRF scores, interleaved by within-tier rank (binding first on ties).** Stratified top-k = 3 tiers × `per_tier_k` (3) = 9 = pooled `top_k`. | Equal context budgets make the configs comparable; the interleaving keeps rank-based metrics (MRR) meaningful. |
| D-026 | **The safe fallback is an explicit abstention** after one failed repair attempt or an LLM outage, flagged `fallback=true`. | An unvalidated answer is never shown. Fallback rate is a monitored metric. |
| D-027 | **Langfuse traces are written after the answer completes** (spans for retrieval and for each generation attempt, with tokens, cost, latency, validation errors, config name and index version). Tracing errors never break answering. | It keeps the core pipeline testable without Langfuse. Timings are recorded as metadata rather than as span durations. |
| D-028 | **Prompt-injection defence:** source text is wrapped in `<source>` tags, any `<source`/`</source>` inside document text is escaped, and the system prompt says source text is data. Validation is the backstop: an injected instruction cannot produce uncited or tier-inconsistent claims. | Defence in depth; the adversarial tests exercise it with a live model. |
| D-038 | **Generator and judge `max_tokens` 900** (was 1500 / 2000) for the Groq configs. | The Groq free tier rejects requests whose *requested* output exceeds 1,000 tokens per minute, and has a 200k tokens/day cap per model. On the completed stratified draft run the longest answer was 727 output tokens and the longest judge reply 563, so 900 truncates nothing that run produced; the configs remain comparable. |
| D-039 | **An LLM or judge outage aborts the eval run instead of being recorded.** The row is not written; `--resume` redoes it. Unparseable judge output is still recorded (`judge_error`): that is model behaviour, not infrastructure. | A daily-quota hit during the first baseline run was recorded as four "safe abstentions" on answerable questions, which would have unfairly lowered the baseline's scores. Those four rows were removed before resuming. |
| D-040 | **`.gitattributes` pins LF line endings and keeps `data/raw/**` byte-exact.** | On Windows, git's CRLF conversion changed file hashes, so the same corpus produced index `idx-e3216f76…` instead of `idx-2185d086…`. Content-addressed versioning needs byte-identical checkouts. |
| D-041 | **Local fallback model for the app and CLI:** Groq (`qwen/qwen3.8-27b`) first; on a quota, outage or auth error, local Ollama `qwen3:4b`. Daily-quota 429s are classified and **fail fast** (no back-off); they open a circuit for Groq's reported reset time (clamped to 1–60 min), so users aren't kept waiting on doomed calls. Every answer records the provider, model and fallback reason, shown as a badge, a banner and a sidebar status in the UI, a `Model:` line in the CLI, and Langfuse metadata. **Evaluation and judge never fall back** (`use_fallback=False`). | User request: keep working past the free tier, and show which model answered. Silently mixing a 27B and a 4B model would make answer quality unpredictable to users and contaminate evaluations; making the switch visible keeps it auditable. In Docker the container reaches the laptop's Ollama via `host.docker.internal` (`OLLAMA_BASE_URL`). |
| D-042 | **New opt-in config `hybrid_stratified_rerank`:** deterministic AI→tech-neutral query expansion (a 5-rule glossary in `regnav/retrieve/expand.py`), cross-encoder re-ranking (`ms-marco-MiniLM-L-6-v2`) of each tier's top-20 hybrid candidates, and 4 chunks per tier (12 in context). The original three configs are unchanged; their rankings were verified identical (40/40) to the archived runs. | Diagnostics: 97% of gold paragraphs were in the top-40 candidate pool but only 61% reached the context, so the gap was ranking, not recall. Ablation on the 35 answerable drafts (`docs/retrieval_ablation.md`): context recall 0.61 → 0.74 and binding gold hit 0.65 → 0.91, for +1.3 s per query on CPU. MiniLM was chosen over `bge-reranker-base`: similar recall at about 7× lower latency. 4 rather than 5 per tier balances recall against Groq's daily token budget and local-fallback speed. **Caveat:** the glossary was written after inspecting failures on these drafts (look-ahead), so it must be confirmed on the expert gold set. |
| D-043 | **Display-only authority notes** (`data/authority_notes.yaml`, `regnav/authority.py`). A guidance document that explains binding law (the OAIC APP 1.7–1.9 fact sheet, the OAIC AI-products guidance, CPG 230, CPG 235) gets a "⚖️ Explains binding law: …" note on every claim citing it, in the UI and CLI. The "Regulator expects" subtitle no longer says "not itself enforceable". Notes are not used by ingest, retrieval or the prompt, so the index version and eval results are unchanged. | User review found the answer "APP 1.7–1.9 … comes into effect 10 Dec 2026" labelled "Regulator expects · guidance – not itself enforceable", although APP 1.7–1.9 is binding Privacy Act law.
